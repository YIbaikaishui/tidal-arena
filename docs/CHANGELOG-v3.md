## 4. 潮汐调度：把疏散演示变成策略玩法

`src/game/evacuation.js` 重写：

| 机制 | 说明 |
|---|---|
| 12 个出口 | 4 主券洞（340 人/秒，2 组人力）+ 8 次门（150 人/秒，1 组人力） |
| 人力预算 | **10 组**；全开 12 个出口需 16 组 → 必须取舍 |
| 选路 | 就近为主 + 排队时延（封顶）小幅修正 —— 真实人群行为 |
| 服务模型 | 出口 = 服务台，μ = 通行能力；分流团推进速率 = min(步行速率, 分到的服务速率) |
| 分区人流 | 20 个分区人数按确定性权重分布（真实看台有大有小）→ 选址有意义 |
| 调配延迟 | 开关出口需 6 秒"调配中" → 战术节奏 |
| 应急广播 | 3 次，对最拥堵分区疏导 12 秒（Lv.4 解锁） |
| 失败态 | 110 秒时限，滞留即失败，成功率 < 85% 则任务不达成 |
| 评级 | S/A/B/C/D（时间 + 成功率 + 峰值拥堵） |
| 3D 反馈 | 12 个出口闸口状态牌（绿=开 / 红=拥堵 / 灰=关 / 琥珀=调配中） |

## 6.1 终验发现并修掉的两处问题

### 6.1.1 draw calls 超预算（263 > 260）
建筑洞察图鉴原本是 12 个独立 Group × 2 个 Mesh = **24 个 draw call**。
改为 **2 个 InstancedMesh**（圆环 ×12 / 菱形 ×12，`instanceColor` 保留每处不同配色，
每帧写 `instanceMatrix` 保持自转与浮动），24 → 2，draw calls 回到 260 以内。

### 6.1.2 疏散演练在软件光栅下跑不完
本机 headless 仅 ~0.7 fps，而演练需 68.8s 模拟时间（≈ 690 帧）→ 实时要十几分钟，
`audit2.cjs` 里的 420s 等待必然超时，误报成"疏散失败"。

**这不是产品缺陷**：游戏内实测（`tools/evac_test.cjs`）为 68.8s / 成功率 100% / 评级 S / 任务 m5 达成。
问题出在**测法**。已把终验改为**确定性快进**：
在页面内同步调用同一个 `evac.update(0.1)`（与游戏主循环**完全相同的步长**），
JS 单线程保证循环期间不会有 rAF 插进来 → 读数即为精确值，且只花几十毫秒。
实时段仍保留 4 秒用于截取热力图。

> 顺带澄清一个易误判的现象：演练前 ~40s「已疏散 = 0」是**正常的**——
> 人群要等约 40s 排队才首次通过出口（出口按 `cap` 共享吞吐），不是卡死。

### 6.2 成长曲线断链：Lv.5 图鉴解锁根本够不着（死内容）

一次性内容能给的积分只有 **382 XP**（任务 196 + 徽章 5×18 + 洞察 12×8），
而图鉴面板锁在 **Lv.5 = 480 XP** —— 差 98 点。
玩家把 6 个任务、5 枚徽章、12 处洞察全收齐也开不了图鉴，
除非去反复刷疏散演练或反复拍照刷分。

**修法**（不是降门槛，而是把经济调成"收齐即满级"）：

| 来源 | 原值 | 新值 | 小计 |
|---|---|---|---|
| 6 个任务 | 24/24/30/30/40/48 | 不变 | 196 |
| 5 枚徽章 | 18 | **24** | 120 |
| 12 处洞察 | 8 | **16** | 192 |
| **合计** | 382 ❌ | | **508 ✅** |

解锁档位因此变成一条自然的曲线：
Lv2（120）≈ 2 任务 + 2 徽章 · Lv3（240）≈ 4 任务 + 3 徽章 + 4 洞察 ·
Lv4（360）≈ 全任务 + 4 徽章 · Lv5（480）≈ 全任务 + 5 徽章 + 10 洞察。

### 6.3 图鉴未解锁时是个"坏面板"

`syncCodex()` 此前**只在已解锁时才被调用**（`'game:changed'` 监听里带 `if (unlocked('codex'))`），
于是 Lv1 时面板停在 HTML 里的静态 "0/12"，条目列表是空的，
连 `.locked` 锁定样式和「达到 Lv.5 解锁图鉴」提示都不显示 —— 玩家完全不知道该干什么。

**修法**：无论解锁与否都同步面板；未解锁时把面板变成一张**12 条收集清单**
（已找到的条目标绿）+ 一行写明解锁路径与当前进度；
Lv.5 后才逐条展开设计讲解。解锁因此从"隐藏"变成"看得见的里程碑"。

### 6.4 任务可能在"半空"中被判定完成

`walk.start()` 的入场过渡是把相机位置沿直线插值到人眼点，
而这条直线**会从场馆内部穿过**（实测从 hero 机位插值到广场时途经 y≈44m 的顶层环廊）。
原先任务判定不看过渡状态，于是在玩家还在空中时就会触发区域任务。

**修法**：`src/game/index.js` 位置→任务判定增加过渡守卫 ——
`walk.trans.mode === 'in'` 期间不判定，落地后再判。

### 6.5 审计脚本自身的两个问题

- `p.waitForFunction(fn, {timeout})` 把 timeout 传到了 **arg** 参数上（真实超时仍是默认 30s），
  已改为 `waitForFunction(fn, null, {timeout})`。
- 读 `walk.pos` 的时机不对：入场过渡途中读到的是插值假象。
  已改为**等过渡结束后**再读，并同时记录 `groundAt` 落地高度。

### 6.6 任务信标放错了地方（把玩家引到半空 / 埋进看台）

信标的落点必须满足 `walk.groundAt(信标) ≈ 信标 y`，否则玩家会被引导到一个**站不住的位置**：

| 任务 | 原落点 | 实际地面 | 问题 |
|---|---|---|---|
| m2 入口大厅 | s=106 | **42.45m（顶层环廊）** | 信标悬在 42m 高的半空 |
| m4 球员通道 | s=11.8（看台踏面下） | ~2.85m（第一层看台踏面） | 信标埋在看台里，看不见 |

已改为：m2 落在门厅地坪带（s = outerS − 0.6，y=0），
m4 落在贴地的场边硬地（s = L1.s0 − 1.5，通道口）。
洞察 i10「球员通道」同步移到通道口地面。

终验新增常驻断言 `beaconGround`：所有任务信标与地面的高差必须 ≤ 3m。

### 6.7 HUD 的等级 / 积分条不跟随游戏层刷新

`setXP()` 过去只在 UI 自己发分（`addScore`）和初始化时调用，
于是**徽章、洞察、任务、疏散演练**这些由 `src/game/state.js` 加的 XP
**不会更新 HUD 的等级环与积分条** —— 成长循环最关键的读数是死的。
已加 `syncXPFromGame()`，在 `game:changed` 时以游戏层为真源刷新。

### 6.8 审计夹具：headless 截图后 rAF 被节流

`page.screenshot()` 之后，headless 页面偶尔会被浏览器节流冻结 rAF：
此时 `p.waitForFunction`（默认 **raf 轮询**）永远等不到条件 → 直接超时，
于是出现了"漫游停在 44m 半空"的**假象**（实为节流导致的过渡冻结）。
（用 `tools/walk_probe.cjs` 单独复现，行为完全正常：落地广场 y=1.7，任务在落地那一刻达成。）

**修法**：`audit2.cjs` 改用 Node 侧轮询 `waitCond()`（`page.evaluate` + 定时器，不依赖页面 rAF），
并在交互步骤前 `page.bringToFront()` 恢复标签页激活。

### 6.9 主入口根本走不进去（漫游模型漏洞，本轮最硬的一个）

玩家按 `F` 进入漫游、跟着信标走到北门券洞，却发现**进不去** —— 面前是一堵整屏的墙。三层原因：

1. **券洞开口判定用了量化后的 u**。
   `locate()` 的 `u` 被离散到 192 段（约 1.7m/段），偏离主轴 **2m** 就判成"不在券洞里"
   → 主入口只剩一条不到 1m 宽的缝。
2. **顶层环廊下方被当成了楼面**。
   券洞轴线上、顶层环廊（42.45m）下方其实是**贯通到地面的门厅空腔**，
   但地面模型在那一段返回 `L3.cY = 42.45`。
3. **穿墙判定因此把玩家挡在门外**。
   `_resolve` 允许穿过立面线的条件是"券洞内 **且** 两侧地面高差 ≤ 6.5m"，
   而门厅处地面比广场高 42m → 判定失败 → 推回墙外。

**修法**

| 改动 | 内容 |
|---|---|
| `groundAtS(s, u)` → `groundAtS(s, x, z)` | 改为世界坐标签名 |
| 门厅空腔 | 券洞轴线上、顶层环廊下方返回 `0`（地面），实测进深 **8.8m**（z 110.7 → 104.8），内端正好抵住 L3 看台后墙 |
| `inPortalWorld(x, z)` | 券洞开口改用世界距离判定：`min(|x|,|z|) < portalHalfU × 周长 ≈ 9.8m`（券洞净宽约 19.5m） |
| 旧 `inPortal(u)` | 删除（u 版本精度不足） |
| 任务 m2 信标 | 移到门厅内 `s = outerS − 5`（原来落在 42m 高的半空） |

**实测**：从广场 z=200 同步步进 42s 模拟时间 → 玩家走到 **z=104.8**（门厅内，地面 0），
并在路过时自动收录「24m 券洞」洞察。
终验新增常驻断言 `entrance`：玩家必须能从广场走进门厅。

> 这条修复让 SPEC 验收 #10「入口大厅…可进入且相互连通」第一次真正成立。
